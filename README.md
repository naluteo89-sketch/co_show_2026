# CO-SHOW 2026 · Pano360 Studio

Meta Quest 3에서 체험할 **360도 이미지와 움직이는 파노라마 영상**을 만드는 프로젝트입니다. ComfyUI로 콘텐츠를 생성하고, 웹에서 결과를 비교·검수한 뒤 Unity 앱으로 Quest 3에서 감상합니다.

현재 저장소는 **웹 기반 이미지 제작 도구와 Unity 정지 이미지 뷰어**로 구성되어 있습니다. 최종 목표인 360도 영상 생성·재생은 후속 개발 단계입니다. 아래 구현 상태와 기본값은 2026년 10월 20일 파일 점검 기준입니다.

## 웹에서 실행하는 이유

웹 버전의 핵심 가치는 사진 업로드부터 결과 확인까지의 반복 작업을 한 화면에서 처리하는 데 있습니다. 생성 모델은 ComfyUI 서버에서 실행되며, 브라우저는 입력·제어·미리보기를 담당합니다.

| 웹 실행의 이점 | 현재 코드가 제공하는 기능 | 실제 활용 |
| --- | --- | --- |
| 작업 단계 통합 | 사진 업로드 → 분석 → 배치·프롬프트 수정 → 생성 → 결과 확인 | 파일과 노드 화면을 오가는 수작업 감소 |
| 사진별 프롬프트 준비 | LLM의 장면·조명 분석과 고정 LoRA 문구를 조합 | 사진마다 남아 있는 이전 장면 설명을 바꾸기 쉬움 |
| 투영 설정 확인 | EXIF 기반 화각 계산 또는 LLM 추정, 수평선 기반 pitch 계산, 수동 수정 | 기존 고정 화각을 모든 사진에 적용하는 문제를 점검 |
| GPU 작업 분리 | 내 PC 또는 별도 PC의 ComfyUI 선택 | 조작 PC에 생성용 GPU가 없어도 서버에 작업 요청 가능 |
| 빠른 구면 검수 | WebGL 파노라마 드래그·확대·축소 | Unity를 빌드하기 전에 왜곡·이음새 후보를 확인 |
| 반복 실험 기록 | 프롬프트·배치·시드·결과·실행 워크플로 저장 및 설정 다시 불러오기 | 잘 나온 조건과 실패 조건을 추적 |
| Unity 전달 | 최종 JPG 복사와 photos.json 갱신 | 선택한 이미지를 앱 콘텐츠로 추가 |
| 같은 네트워크에서 접근 | 서버를 LAN에 바인딩하면 다른 기기의 브라우저로 접속 가능 | 제작 PC와 검수 기기를 나누어 사용 |

웹으로 옮겼다는 이유만으로 원본 디테일, 생성 속도 또는 VR 몰입감이 향상되지는 않습니다. 생성 시간은 GPU·모델·워크플로에, 화질은 입력 투영·생성·업스케일에 영향을 받습니다. 현재 기록 기능은 같은 모델·노드 환경에서 비교하는 데 도움이 되지만, 모델 파일의 해시와 노드 버전까지 자동 고정하지는 않습니다.

**권장 운영 방식은 웹에서 제작·선별하고, Quest 3의 Unity 앱에서 최종 체험을 검수하는 것입니다.**

## 웹 미리보기와 Quest 3 체험의 역할

| 구분 | 현재 웹 Studio | 현재 Unity 뷰어 |
| --- | --- | --- |
| 주된 역할 | 이미지 제작·기록·구면 미리보기 | 헤드셋에서 이미지 감상 |
| 표시 방식 | 브라우저 캔버스의 WebGL 렌더링 | OpenXR 기반 VR 렌더링 |
| 시점 조작 | 포인터 드래그, 휠로 화각 변경 | 머리 회전, 컨트롤러·핸드트래킹 입력 코드 |
| 콘텐츠 변경 | 웹 화면에서 새 결과 확인 | 앱 포함 이미지는 다시 빌드하거나 기기 Photos 폴더에 별도 복사 |
| 영상 | 생성·재생 UI 미구현 | VideoPlayer 연결 미구현 |
| 브라우저 몰입형 VR | WebXR 미구현 | Android 앱 경로 사용 |

웹 Studio는 Unity WebGL 빌드가 아니라 Python 서버와 HTML/JavaScript로 만든 별도 도구입니다. 현재 페이지를 Quest Browser에서 열더라도 자동으로 머리 추적과 양안 렌더링을 제공하는 몰입형 VR 페이지가 되지는 않습니다.

APK 없이 링크로 몰입형 체험을 배포하려면 WebXR 세션, 눈별 렌더링, 입력 처리와 실기기 성능 검증을 추가해야 합니다. WebXR에는 지원 브라우저와 보안 컨텍스트가 필요하므로 기기 간 접속에서는 HTTPS 구성도 고려합니다. [WebXR Device API](https://developer.mozilla.org/en-US/docs/Web/API/WebXR_Device_API)

## 전체 제작 흐름

```text
원본 사진
  → 웹 업로드 및 원본 저장
  → OpenAI 이미지 분석: 장면·조명·화각·수평선
  → 작업자가 프롬프트와 yaw/pitch/hFOV 확인·수정
  → Python 서버에서 2048×1024 ERP 제어 PNG 생성
  → 선택한 ComfyUI 서버에 업로드 및 워크플로 제출
  → 360도 아웃페인팅과 좌우 이음새 보정
  → AI 업스케일·블렌딩·디더 후 8192×4096 출력
  → 웹 서버에 PNG 및 Quest용 JPG 저장
  → 구면 미리보기와 이전 시도 비교
  → Unity 콘텐츠 폴더로 복사
  → Quest 3에서 최종 검수
```

ERP는 전 방향을 2:1 직사각형으로 펼친 이미지입니다. 일반 사진이 담지 못한 뒤쪽·천장·바닥은 AI가 추정하여 채웁니다. 이 결과를 구 안쪽에 표시하는 것이 파노라마 스피어이며, 자유롭게 이동하며 물체 뒤를 볼 수 있는 3D 공간 복원은 별도 과제입니다.

사진 분석 시에는 이미지의 분석용 사본과 입력 메모가 OpenAI API로 전송됩니다. 생성 시에는 ERP 제어 이미지와 프롬프트가 선택한 ComfyUI 백엔드로 전송됩니다. 브라우저 자체가 생성 모델을 실행하지는 않습니다.

## 웹 Studio 실행

### 1. 실행 환경 준비

- Python 3.10 이상: 현재 코드의 타입 표기 기준
- Python 패키지: `aiohttp`, `Pillow`, `numpy`
- WebGL을 사용할 수 있는 브라우저
- 실행 중인 ComfyUI 서버와 워크플로에서 사용하는 모델·노드
- 사진 분석에 사용할 OpenAI API 키와 사용 가능한 이미지 분석 모델

일반 Python 환경에서 저장소 루트 기준으로 실행합니다.

```powershell
python -m pip install aiohttp pillow numpy
python .\pano360_web\main.py
```

브라우저가 자동으로 열리며 기본 주소는 [http://127.0.0.1:7870](http://127.0.0.1:7870)입니다. `pano360_web\run.bat`도 같은 진입점을 실행합니다.

`python` 명령을 찾지 못하면 Python을 설치하거나 ComfyUI의 Python 실행 파일을 지정합니다. `run.bat`에서는 `PY` 값을 실제 경로에 맞춥니다. 기존 ComfyUI 환경을 이용하더라도 필요한 패키지의 설치 여부는 확인해야 합니다.

### 2. 설정 확인

[pano360_web/config.json](pano360_web/config.json)의 주요 항목입니다.

| 항목 | 현재 값 또는 역할 |
| --- | --- |
| workflow | ../test_quest3.json |
| erp_size | 2048×1024 |
| final_tag | 8k |
| jpg_quality | 95, 서버에서 색차 서브샘플링 없이 저장 |
| runs_dir | pano360_web 기준 runs |
| viewer_dir | ../Pano360Viewer/Assets/StreamingAssets/Pano360 |
| openai_model / openai_models | 기본 분석 모델과 화면 선택 목록 |
| node_ids | 입력 이미지·프롬프트·샘플러·저장 노드의 ID |
| model_fallbacks | 업스케일 모델이 없을 때 조회할 대체 후보 |

설정에 들어 있는 분석 모델 이름과 실제 API 계정에서 호출 가능한 모델은 별도로 확인합니다. `OPENAI_MODEL` 환경변수로 기본 모델을 덮어쓸 수 있으며, 화면에서 선택할 수 있도록 `openai_models`도 함께 맞춥니다.

현재 키 로딩 설정은 다음과 같습니다. 키 값은 저장소에 넣지 않고 해당 파일 또는 환경변수로 제공합니다.

| 용도 | 설정된 키 파일 | 우선 조회 환경변수 |
| --- | --- | --- |
| OpenAI 사진 분석 | C:\keydata\gpt_key | open_Aikey |
| 공식 Comfy Cloud 사용 시 | C:\keydata\comfy_key | comfy_key |

같은 이름의 환경변수가 파일보다 우선합니다. 현재 웹 화면의 새 작업 흐름은 사진 분석 이후 편집·생성 화면으로 이어지므로, 분석용 키와 모델 설정이 필요합니다.

### 3. ComfyUI 백엔드 확인

| 설정 이름 | 실제 타입 | 현재 주소 |
| --- | --- | --- |
| cloud | comfyui | http://192.168.1.91:8000 |
| local | comfyui | http://127.0.0.1:8188 |

**현재 cloud라는 설정 이름은 LAN에 있는 일반 ComfyUI 서버를 가리킵니다.** 공식 Comfy Cloud 서비스 연결과는 구분합니다. 공식 서비스용 `comfy_cloud` 어댑터 코드는 있으나 기본 설정에는 활성화되어 있지 않습니다.

ComfyUI 서버에는 다음 모델과 워크플로의 노드가 필요합니다.

- `flux-2-klein-base-4b-fp8.safetensors`
- `qwen_3_4b.safetensors`
- `flux2-vae.safetensors`
- `flux-2-klein-4B-360-erp-outpaint-lora_V1.safetensors`
- `4x_NMKD-Siax_200k.pth` 또는 설정의 호환 가능한 4배 업스케일 대체 모델

서버는 ComfyUI의 모델 목록을 조회하여 하위 폴더가 다른 파일명을 맞추고, 업스케일 모델이 없으면 설정된 후보를 찾습니다. 모델을 다운로드하거나 설치하는 기능은 아닙니다. 대체 모델에 따라 결과가 달라지므로 실제 선택된 모델은 시도별 `workflow_api.json`에서 확인합니다.

### 4. 사진 생성과 저장

1. 웹 화면에 원본 사진을 업로드합니다.
2. 분석 모델과 작업 메모를 선택한 뒤 사진을 분석합니다.
3. 한국어 분석 요약, 화각·수평선 추정, 생성 및 이음새 프롬프트를 검토합니다.
4. `yaw`, `pitch`, `hFOV`, 필요 시 `vFOV`를 수정하고 ERP 제어 이미지를 확인합니다.
5. 백엔드와 두 샘플러의 시드를 정한 뒤 생성합니다. 시드를 비워 두면 임의 값이 사용됩니다.
6. 완료된 결과를 드래그·휠로 검수하고 PNG 또는 JPG를 내려받습니다.
7. 채택할 결과에서 **Quest 뷰어에 추가**를 누릅니다.

마지막 버튼은 웹 서버가 실행 중인 PC의 Unity 프로젝트 폴더에 JPG를 복사하고 목록을 갱신합니다. Quest 기기에 직접 전송하거나 APK를 자동 빌드하는 기능은 아닙니다.

작업 기록은 다음 위치에 저장됩니다.

```text
pano360_web/runs/<작업 ID>/
├─ source.<확장자>       업로드 원본
├─ meta.json             분석·배치·프롬프트·시드·시도 상태
├─ control.png           편집 중 제어 이미지
└─ a01/                  생성 시도별 폴더
   ├─ control.png
   ├─ workflow_api.json  모델명 보정 후 제출한 워크플로
   ├─ result_2k.png
   ├─ result_8k.png
   └─ <작업 ID>_a01_8k.jpg
```

현재 결과 다운로드·로컬 저장은 화면의 상태 조회 요청을 처리할 때 실행됩니다. 생성 중 서버와 결과 화면을 유지하고, 완료 표시와 파일 저장을 확인합니다. 브라우저나 서버 종료 후의 자동 수집·작업 복구는 추가 보강 대상입니다.

### 5. 같은 네트워크에서 접속

```powershell
python .\pano360_web\main.py --host 0.0.0.0 --port 7870 --no-browser
```

다른 기기에서는 `http://<Studio 실행 PC의 LAN IP>:7870`으로 접속합니다. 해당 PC의 방화벽과 네트워크에서 포트 접근이 가능해야 합니다. ComfyUI 주소는 브라우저가 아니라 Studio 서버가 접속할 수 있는 주소로 설정합니다.

현재 서버에는 사용자 인증과 작업별 접근 권한이 없으며 업로드 파일과 생성 API를 제공합니다. 따라서 공유는 신뢰할 수 있는 내부 네트워크 범위로 한정합니다. 인터넷 공개 운영에는 인증·HTTPS·작업 격리·사용량 제한을 추가해야 합니다. 현재 구조는 다중 사용자 동시 편집과 같은 작업의 동시 생성 요청을 안전하게 조정하는 협업 서비스로 검증되지 않았습니다.

| --- | --- | --- | --- |
| test.json | 2048×1024 | Lanczos 확대 | 4096×2048 |
| test_quest3.json | 2048×1024 | 좌우 128px 패딩 → AI 4배 확대 → 패딩 제거 → AI 80%·Lanczos 20% 혼합 → 노이즈 0.004 | 8192×4096 |

위 값은 저장된 워크플로 설정입니다. 웹의 기본 워크플로는 두 번째이며, 기존 JSON 내부 설명 노트에는 과거 4K 설정과 다른 샘플러 값이 남아 있으므로 실제 노드 설정을 기준으로 확인합니다.

**8K 저장은 8K 원본 디테일 확보를 보장하지 않습니다.** 패딩도 이음새 완화를 위한 처리이며, 생성된 구조가 자연스럽게 연결되는지는 별도 검수가 필요합니다. 8K가 모든 장면에서 최적이라는 결론 역시 실기기 비교로 정해야 합니다.

현재 흐릿함·늘어짐을 확인할 지점은 세 곳입니다.

1. **입력 전처리:** HTML 도구와 Python ERP 생성기 모두 원본을 미리 축소합니다. 가로 2048 ERP와 약 97도 화각에서는 원본의 전처리 폭이 최대 약 828px이고, 참조 영역은 적도 기준 약 551개의 가로 샘플에 해당합니다. 웹 실행만으로 이 손실이 사라지지는 않습니다.
2. **생성·보정:** AI가 사진에 없는 공간을 채우며 형태와 질감을 바꿀 수 있습니다. 제어 이미지, 2K 보정 결과, 8K 결과를 같은 방향과 화각으로 비교해야 합니다.
3. **미리보기:** 현재 WebGL 뷰어의 초기 FOV는 세로 90도이며 가로 화각은 화면 비율에 따라 더 넓어집니다. 주변부가 과하게 늘어 보이면 휠로 화각을 좁히고 해당 물체를 중앙으로 옮겨 비교합니다. 브라우저의 최대 텍스처 크기를 넘는 이미지는 미리보기에서 축소됩니다.

EXIF의 35mm 환산 초점거리는 현재 코드에서 근사 화각으로 변환하며, EXIF가 없으면 LLM이 추정합니다. 크롭한 사진이나 수평선이 모호한 장면에서는 사람이 값을 확인해야 합니다. 원본 배치용 hFOV와 뷰어에서 보는 FOV는 서로 다른 설정입니다.

## Unity와 Quest 3에서 확인하기

Unity **6000.3.26f1** 및 Android Build Support가 필요합니다. 현재 패키지 설정에는 OpenXR 1.18.0과 XR Hands 1.9.0이 포함되어 있습니다.

1. Unity Hub에서 `Pano360Viewer`를 엽니다.
2. 패키지 설치 후 Pano360 메뉴의 Android 전환·XR 설정을 적용하고 Project Validation을 확인합니다.
3. 웹에서 복사한 사진과 `photos.json`을 확인합니다.
4. 개발자 모드·USB 디버깅을 설정한 Quest 3를 연결하고 Build And Run을 실행합니다.
5. 정면·뒤쪽·좌우·천장·바닥의 화질과 이음새를 확인합니다.

상세 절차와 입력 조작은 [Unity 뷰어 README](Pano360Viewer/README.md)를 참고합니다. 기기 내 `/sdcard/Android/data/com.witches.pano360/files/Photos/`에 사진을 별도 복사하는 경로도 있습니다.

파일명에 `_TB`, `_OU`, `_3D`가 포함되면 Unity 뷰어는 상하 스테레오로 해석합니다. 모노 이미지에는 이 표기를 사용하지 않습니다.
